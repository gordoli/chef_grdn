# Architecture

Next.js 16 App Router + React 19 + strict TypeScript. Tailwind 4 supplies utilities; `src/styles.css` composes ordered theme layers from `src/theme`. `theme/tokens.css` owns colors, spacing, typography, rounding and motion; `theme/STYLE_GUIDE.md` documents their roles and geometry exceptions. `npm run theme:check` enforces token use in feature CSS and visual size/duration tokens across theme layers. Poppins is the single family. Public recipes render on the server and refresh in the browser. Fonts are served locally through next/font.

## Boundaries

- `components/ui`: locally owned shadcn-style Button, Input/Textarea, and Radix Dialog primitives. `cn` combines variants and merges utility classes. Domain components reuse these accessible primitives.
- `src/app`: native Next.js pages, layouts, metadata, manifest, and API Route Handlers.
- `views`: client-side collection, editor, gallery, recipe sheet, and email/password sign-in and password recovery.
- `lib/publicRecipes.ts`: cached, anonymous-only Supabase reads for the server-rendered collection. No private profiles, reviews or sessions enter this cache.
- `hooks/RecipeProvider.tsx`: recipe queries/mutations and preview persistence. `useRecipes.ts` holds the context contract/hook; presentation does not query the database directly.
- `hooks/SessionProvider.tsx`: session lifecycle and editing gate; browsing does not require a session. Profiles and RLS enforce owner access. Session and recipe refreshes guard stale responses. Editing and moderation controls require a live session whose user ID matches the owner profile, so an earlier account’s role cannot carry across sign-out or account switching.
- `lib/quantity.ts`, `recipeText.ts`: pure parsing, scaling, formatting, and editor round trips. Raw ingredient strings remain authoritative at factor 1.
- `lib/photos.ts`: EXIF-aware client resizing, uploads and batched expiring signed URL cache. Stored photos retain captions, order and cover identity.
- `server`: bounded recipe HTML/JSON-LD and binary image import; curated publisher/CDN allowlists, validated redirects, MIME/signature checks, timeouts, per-owner in-memory quotas. All URLs are untrusted. No browser CORS proxy.
- `src/app/api`: Next.js Route Handlers. Each verifies the session with Supabase and verifies `profiles.role = owner` before invoking import services. Only the public key is required on the server.
- `supabase/migrations`: schema, RLS, public portfolio reads, favorites and owner photo cleanup. `upsert_recipe` remains service-role-only and keeps its original JSON contract.

## Data and access

Anonymous visitors read recipes and recipe photos; Storage buckets remain private with explicit recipe-photo read policies. Review photos, profiles and reviews are visible only to signed-in users. Anonymous favorites stay in localStorage. Authenticated favorites are scoped by `auth.uid()`. Every recipe/photo mutation is owner-only under RLS. Recipe cooking status (`made` / `to_try`) is shared across the book and owner-editable. Existing recipes and legacy preview JSON count as made; new recipes default to to-try. The Recipes page starts with made recipes, and its status filter composes with favorites, category and search. Status changes use a separate mutation so editor saves and `upsert_recipe` preserve them. Invitees may write only their own reviews. Users may update their display name, never their role.

`/demo` is an explicitly labeled, isolated browser-only copy of the eight seed recipes. It cannot write to Supabase or invoke import APIs. Preview edits and favorites use distinct storage keys.

The installable manifest keeps the existing pixel-chef icons. The service worker retires the previous Vite app-shell cache; it does not cache Supabase records, signed photos or Next.js navigation responses. Next.js owns page and asset delivery.

Recipe pages publish their own title, canonical URL and Open Graph/Twitter preview. `/r/[slug]/share-image` renders a square cover photo beside the recipe title using local Poppins and pixel-chef assets; without a photo, the text uses the full width and aligns left. Only anonymous portfolio data and bounded, validated recipe-photo storage images enter previews. Image URLs include the preview layout version, recipe revision and cover ID, so edits get a fresh URL. Metadata is included in the initial HTML head for messaging clients. Empty or generic filler introductions are omitted from the recipe sheet.

Copy recipe link includes the same revision in a `share` query parameter, while canonical URLs stay clean. This gives messaging clients a fresh page URL after edits instead of repeatedly using an earlier icon-only preview; existing messages remain controlled by the messaging app's cache. Portion parameters are preserved.

Liquid-glass styling uses one shared `.glass-control` material for navigation and floating controls: neutral translucent fills, backdrop blur, edge highlights and inset/ambient shadows. Content surfaces stay black/white. Green is reserved for primary actions and meaningful ingredient states. Reduced-motion and reduced-transparency preferences have fallbacks.

The shared layout omits the former leaf tagline and Instagram footer. The header exposes Search, Kitchen basics, and Settings in that order. Settings contains theme and account actions; Basics is outside the main navigation. Layout owns shared collection search state so the header can reveal and focus the collection search, including from another page. In the Restaurants section, the header search targets restaurants and their locations instead. Search closes on outside clicks, its toggle, or Escape; hidden controls are inert. Category filters stay in a horizontally scrolling row.

Recipe and restaurant creation share `components/ui/add-sheet.tsx`: a Radix sheet, circle back control, simple title, source-choice cards, and step progress. `theme/add-sheet.css` owns its responsive frame and motion: a side sheet on desktop and a bottom sheet that slides up on mobile, with reduced-motion support. Both start with Import or Enter manually. Restaurant imports then offer Website, Yelp, or TikTok. Recipe imports go straight to a URL field, then the same editable form used by manual entry. Recipe entry uses Main details, Ingredients & method, then Photos & source; only the final step saves. `hooks/useRecipeEditor.ts` owns import/save coordination and pending media, while `lib/recipeEditor.ts` validates import payloads and routes step errors. Existing ingredient/method parsing, recipe JSON, source attribution and upload behavior are preserved. The recipe plus control opens `?add=1` over the collection, consumes the flag, and `/new`/`/demo/new` redirect there for compatibility. Existing recipe editing uses the same sheet with all fields. Titles are simply Add recipe / Add restaurant (or Edit for existing entries); decorative editor introductions are omitted.

Main navigation is Recipes → Restaurants. Gallery is no longer a main navigation tab; existing gallery URLs remain available. The dice control beside the restaurant list/map controls opens `RestaurantRoll` as a Radix app sheet over the existing collection; it preserves the underlying view, filters and scroll position. Its single prompt is What are we feeling?, with a Been to / Want to try / Both toggle (Both by default), multi-select cuisine pills and a Roll action. The status and cuisine filters compose without relaxing either filter when there are few matches. `hooks/useRoll.ts` coordinates cuisine selection and a four-second local animation before revealing up to three distinct restaurant suggestions. `lib/roll.ts` owns OR matching and selection: both visited/want-to-go statuses appear when possible, rerolls prefer unseen entries, and small pools stay honest. The CSS duration is shared with JavaScript through `theme/motion.ts`; reduced-motion skips the wait, and unmount clears the timer. The sheet uses transform/opacity animation, a CSS 3D die, fixed frame, and a scrollable body with a persistent footer. Existing `/roll` and `/demo/roll` URLs redirect to the collection and open the sheet once; the query flag is consumed without a new history entry. Demo Roll uses the isolated browser restaurant collection and makes no mutations. Recipe JSON and `upsert_recipe` are unchanged.

Recipe details keep Radix dialog focus and keyboard behavior while presenting a sliding page with a back chevron. `useRecipePanel` coordinates entry/exit, navigation after closing, and rightward pointer gestures; `recipeSwipe` classifies deliberate swipes. Vertical scrolling, interactive controls, photo strips, nested dialogs, and mouse text selection are excluded from dismissal. Reduced motion skips the transition.

Recipe collections live in `(recipes)` route groups for live/demo browsing. Their parallel `@modal` slots intercept recipe links while leaving the original `Home`, selected filters, loaded images and scroll position mounted. Recipe editors remain outside these groups, so editing and direct/shared links keep their existing full-route behavior. Collection detail links prefetch their routes and disable page scrolling. Back closes intercepted sheets through history; direct-link sheets replace with the collection instead of navigating outside the app. Portion changes replace the detail URL without remounting the sheet or clearing ingredient checks. The collection search is retained during detail navigation; opening a result does not trigger outside-click cleanup.

`components/ui/detail-panel.tsx` owns the shared accessible recipe/restaurant frame and close context. Intercepted-route layouts mount it outside their `loading.tsx` boundaries. `DetailSkeleton` therefore appears inside the final frame during loading, and replacing it with content does not replay the entry animation. Both detail views prioritize their first photo while later recipe photos load lazily. Shared motion tokens use 120 ms for feedback, 180 ms for dismissal and 240 ms for panel entry. The intentional four-second Roll sequence is unchanged. Card hover effects apply only above the mobile breakpoint with a fine, hover-capable pointer; keyboard focus remains visible.

Restaurant detail links use parallel `@modal` slots and intercepted routes in both live and demo collections. Soft navigation opens a Radix detail panel while leaving the collection, decoded thumbnails, filters and scroll position mounted underneath. Closing waits for the shared detail-panel exit before navigating back; browser Back/Forward closes/reopens the intercepted route. Direct links and reloads render the standalone server page with the same metadata. Only the outer panel animates, and its first hero image loads eagerly. The shared header stays mounted, hidden and inert on detail screens, preserving the underlying collection geometry; standalone restaurant pages offset the reserved header height using `--size-site-header`.

## Intentional limits

`/basics` and `/demo/basics` share a public kitchen reference with linked primary sources. Conversions opens first; headings stay brief and practical. Culinary steak doneness is distinguished from USDA minimum cooking temperatures. The converter uses US customary volume and avoirdupois weight; it never infers ingredient density. Favorites are a filter on Recipes; the former favorites URLs remain compatible. Mobile recipes always use the compact list presentation while desktop layout preferences remain independent.

The default collection groups recipes by type: Mains, Appetizers, Soups, then the remaining categories. `lib/recipeCollection.ts` owns display names, ordering, and grouping; existing Starter/Appetizer aliases are grouped together without rewriting saved records. Search and favorites omit empty sections. Alternate sorts remain flat.

Website scraping depends on publishers allowing requests and providing structured data. Unsupported sites and social video posts use the manual editor. The Instagram public profile embed is controlled by Instagram and has a direct link fallback; it is not a token-backed automatically refreshed media feed. Source images retain attribution. In-memory import quotas are best effort per function instance, suitable for a single-owner portfolio, not a shared abuse-prevention service.

No meal planner, grocery list, nutrition system or additional infrastructure is introduced.

## Restaurants

`/restaurants` is a public restaurant collection with list/map views and two status tabs (Been to, Want to go), and individual `/restaurants/[slug]` pages. The heading and icon tabs reuse the Recipes collection styles and circular heading count; list/map controls sit beside the heading. Compact rows show a small square thumbnail beside the restaurant name, with neighborhoods as muted subtext underneath. Cuisine, numeric price-per-person and social pills remain below, with a favorite heart on the right. Unrated places omit the rating entirely; rated places show five stars, including half stars, left-aligned beneath the pills. The floating add control opens the shared Import/manual source sheet; Website, Yelp, and TikTok imports lead to an editable four-step form before any database write: main details (including address/neighborhood confirmation), gallery/thumbnail selection, personal experience, then social links. The Been here / Want to go toggle skips personal experience for places to try. Restaurant websites and primary Yelp listings are stored independently (`website`, `yelp_url`, migration 0009); per-branch source links remain in `yelp_data`. Yelp and TikTok use owner-only, source-bound signed asynchronous Bright Data jobs with bounded results and a server-only `BRIGHTDATA_API_KEY`. The dedicated Gallery step shows all saved/imported photos, supports inclusion/exclusion, and lets the owner select a thumbnail or keep the automatic first-photo default. Migration 0010 adds nullable `thumbnail_url` under existing owner-only RLS. A selected image is retained across later imports, and removing it restores the default. Picker order stays stable while selecting a cover; board/detail/share presentation uses the chosen cover first. Clipboard paste is user-initiated unless read permission already exists; the browser does not prompt for access just by opening a sheet. TikTok imports preserve the canonical video URL and show the caption for review. Only explicit location lines become suggested names/addresses; prose is not guessed, and captions never overwrite personal notes. Instagram and TikTok posts produce compact branded pills on collection rows. The add query parameter is consumed so the sheet can be reopened. Saved photos remain available on restaurant detail pages. Public Yelp CDN images use allowlisted Next.js optimization with separate thumbnail/preview/gallery sizes; local-network targets and redirects are rejected, oversized sources are bounded, and failed optimization falls back to the original then a neutral placeholder. Other HTTPS images remain native browser loads. Demo records wait for local restoration to avoid briefly showing stale seed covers. The owner edits the collection, personal notes/rating, visit date, and dining companions. These owner-authored fields are public portfolio data. Friend reviews live in `restaurant_reviews`; they are authenticated-only and scoped to their author for writes, with owner moderation for deletion. RLS and constraints are defined in migration 0006. Migration 0007 adds bounded JSON locations (neighborhood, address, phone, latitude/longitude) and merges Dumpling Story while preserving reviews and personal fields. Legacy scalar location fields remain compatible; location arrays drive cards, search, details, map pins and share previews. Previous Dumpling Story URLs redirect to its canonical page. Favorites is the first filter after All, matching Recipes, and composes with visit status, cuisine and search. All clears Favorites and cuisine together. Counts and available cuisines reflect the selected status and Favorites filter. Cuisine filters are a horizontally scrolling row of pills derived from that filtered collection. `restaurantCuisineRegions` groups dish/style labels under countries or regions (Chinese / Dim sum and Cantonese become Chinese; Japanese / Ramen becomes Japanese; Pizza becomes Italian). Multi-region restaurants can match either region. Changing collection tabs resets the cuisine filter. There is no collection-order control. Recipe JSON and `upsert_recipe` are unchanged.

`hooks/useRestaurantEditor.ts` owns draft state, import lifecycle and save coordination; pure merge/save preparation is in `lib/restaurantEditor.ts`. The view composes source forms and a fixed-height wizard, preserving focus and footer position across steps. `hooks/RestaurantProvider.tsx` owns persistence, session-sensitive review reads, mutations, and stale-request guards. `lib/restaurants.ts` validates inputs and derives safe social embed links. Anonymous restaurant reads use a tagged, 60-second server cache and request-local memoization. Owner writes invalidate that public cache immediately through an authenticated route, keeping revisioned share previews fresh. The browser shares a bounded public restaurant snapshot across provider remounts and deduplicates concurrent loads; private reviews never enter that snapshot. The custom share-image route uses local Poppins/mascot assets and a bounded, validated website image, with a text-only fallback. Messaging metadata renders in the initial head, as with recipes. A preview image revision changes with `updated_at`.

`server/restaurantImport.ts` extracts restaurant JSON-LD and website photos for owner review before saving. `restaurantFetch.ts` validates public HTTPS URLs, resolves and rejects non-public DNS addresses on every redirect, and pins the validated address to the TLS connection. HTML/images have byte and time limits; images used in share cards are decoded with pixel bounds. Website ratings never become the owner's rating. Dollar-sign price tiers stay distinct from numeric prices per person. Migration 0008 stores bounded `yelp_data` per branch: source URL, retrieval time, contact details, hours, Yelp rating/review count, price tier, and up to five attributed reviews with photos. `server/restaurantSocialImport.ts` owns fixed-origin provider requests, signed job tickets, per-owner quotas and bounded input/output parsing. Progress endpoints run concurrently; completed payloads are downloaded only when both collections are ready, within the function time budget. Operational limits and freshness/signing policies live in `src/config/loading.ts`. `lib/restaurantYelp.ts` validates and merges business information while preserving personal notes, rating, visit status, companions, favorites, curated cuisine, numeric prices, and existing media. Yelp ratings appear separately from personal and friend ratings; review photos join the gallery with source links. Missing fields remain editable. Anonymous reads expose only this public restaurant metadata; owner-only restaurant writes and private friend-review permissions remain unchanged. `restaurantGeocode.ts` optionally resolves a single unambiguous US business address through the fixed-origin Census API. Map rendering uses lazy-loaded Leaflet and attributed OpenStreetMap tiles; unconfirmed locations have direct map-search links. No map key is required.

Instagram posts/reels and full TikTok video links are stored as URLs, not arbitrary HTML. The Videos tab derives fixed-provider iframe URLs and always offers a direct link; private, removed, or platform-restricted posts may not embed. `/demo/restaurants` uses a separate localStorage copy and cannot invoke import APIs or write reviews/database rows. `seed/restaurants.json` contains 28 places (one Dumpling Story with Mission/Pacific Heights locations, Amarin in Lafayette, and the requested removal of La Taq/El Faro), with seven places marked want-to-go, including Ah Ma’s Kitchen and Aziza from the supplied TikTok links. Their full canonical video URLs are attached, contact details match their official websites, and map coordinates come from Census address matches. Personal ratings and visit dates remain unset. Reported numeric price ranges and their research provenance are recorded in `seed/restaurant-pricing-sources.json`; missing reliable ranges and uncertain chain branches stay blank. Owner-supplied image links are saved first in their galleries. `npm run seed:restaurants` inserts missing slugs without overwriting existing entries.

Both share renderers reuse local assets from `server/shareAssets.ts` and fixed-canvas presentation values in `theme/shareCard.ts`. Collection search focus/outside-click cleanup is shared by `hooks/useCollectionSearchDisclosure.ts`. Global navigation lives in `components/Navigation.tsx`: its measured selection highlight slides between tabs, with reduced-motion support and an active-link fallback before the first client measurement. `lib/navigation.ts` derives the selected app section on the first render: restaurant routes select Restaurants, and recipe/utility routes default to Recipes. A zero-size hidden navigation never replaces that fallback with an empty highlight. CSS motion tokens drive detail-dismissal fallback timing; physical swipe thresholds are documented in `theme/gestures.ts`. Main tab links prefetch full routes, and Next.js retains page segments for 60 seconds. Recipe and restaurant detail/edit routes hide the global header and retain their own back/share controls. Anonymous recipe and restaurant pages reuse server-provided records without an immediate duplicate collection fetch; focus refreshes are throttled to the cache lifetime. Anonymous recipe loads do not query private profiles or reviews, and sign-out clears review state.

Both recipe and restaurant sheets support rightward touch swipes. Vertical scrolling and pinch zoom stay native; multi-photo recipe strips keep their horizontal scrolling. Single recipe photos and restaurant hero photos may start a touch swipe, with the trailing click suppressed so dismissal cannot also open a photo. Buttons, form fields, links and nested dialogs keep their own interactions. Mouse drags are limited to the two detail topbars. `detailSwipeIntent` decides direction before pointer capture; both sheets use the same tested distance/velocity thresholds.

`components/ui/segmented-control.tsx` shares the measured `useSlidingIndicator` hook and `.selection-highlight` material with global navigation. Recipe cooking status, restaurant visit status, the restaurant list/map toggle, Roll status and the restaurant editor visit toggle use this component, preserving their pressed-button semantics, initial selected fallback and reduced-motion behavior.

TikTok shared links (`/t/`, `vm.tiktok.com`, `vt.tiktok.com`) resolve on the server before a Bright Data job starts. Header-only requests validate and pin public DNS addresses; each redirect must remain a supported HTTPS TikTok link, with a shared deadline and bounded hops. The signed job uses the resolved video URL, so result matching checks the exact video ID. Full links avoid the extra request.

TikTok previews keep explicit city/location hints separate from street addresses. Find on Yelp opens the existing Yelp import flow without clearing the draft; Search Yelp prefills the current name and location on Yelp’s website. The owner selects a listing and pastes its business URL to import details and review photos, preserving the TikTok video and personal fields. This is a user-confirmed search, not automatic business matching, and requires no additional API key. Nothing saves until the final Save restaurant action.
